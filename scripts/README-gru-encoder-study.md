# Feature encoding and separate inference comparison

This is a mechanism comparison in the maintained LKT package, not an exact
reproduction of UNVaMP's unpublished winning architecture. All four main
conditions retain a three-layer, 32-unit GRU and one 128-unit prediction-head
hidden layer: plain, encoders only, inference only, and encoders plus inference.

Optional feature encoding uses independent learned response, time-gap and
numeric-auxiliary towers. Each tower has a ReLU hidden layer of width 16 or 32
and a 16-coordinate linear output. A tower is omitted when its input block is
absent. Item/skill IDs retain their learned 16-coordinate embeddings. Encoded
responses enter only completed interactions; current-response information never
enters its own prediction. Numeric and engineered input choices remain specific
to the matched, raw and augmented families. Current engineered predictors can
depend on the current item; no item-independent proficiency interpretation is
claimed. Inference vectors are never fed back into recurrent memory.

Public controls are `feature_encoder`, `encoder_hidden_sizes`,
`encoder_output_size`, `encoder_activation`, and `encoder_dropout`, alongside
the existing inference controls. All are in saved configurations and the FGUI.
Disabling encoding retains historical network weight names and behavior.

## Exact encoder-only augmented figure

The [second network figure](../docs/figures/gru-encoder-augmented/gru-encoder-network.svg)
builds on the [original augmented GRU figure](../docs/figures/gru-head128/gru-network-overview.svg).
It depicts development candidate `g112`, which has mean test AUC 0.841792
across three seeds on the original participant split. Its three independent
encoders each have a 32-unit ReLU hidden layer and a 16-value linear output:
time `1 -> 32 -> 16`, LKT history features `4 -> 32 -> 16`, and observed
answer `1 -> 32 -> 16`. Item and skill embeddings remain 16 values apiece.

The input encodings total 64 values; the answer encoding is appended only after
prediction, giving the first GRU layer 80 input values. The prediction head is
`96 -> 128 -> 1` because it combines 32 previous-memory values with 64 current
inputs. All three GRU layers still have 32 units. There is no separate student
inference network in this model. The intercept is retained among the four LKT
coordinates and becomes zero after training-mean standardization.

The representative checkpoint is seed 3, selected by its validation loss, restored
at epoch 18. All seeds of this candidate share the same architecture and 40,945
parameter entries. This describes the best original-split architecture so far,
not a cross-validation winner.

[Overview PDF](../docs/figures/gru-encoder-augmented/gru-encoder-network-overview.pdf)
and [full PDF with before/after dimensions](../docs/figures/gru-encoder-augmented/gru-encoder-network.pdf)
are generated by [draw-gru-encoder-network.R](draw-gru-encoder-network.R).
The generator verifies the current installed release, saved configuration, weight
shapes, independent encoder/GRU/head equations, causal answer ordering and a real
held-out response history. It never retrains or changes a fitted checkpoint.

## Frozen search

For each input family, the deterministic grid has 54 configurations:

| Condition | Configuration axes | Settings |
|---|---|---:|
| Plain | Learning rate {0.001, 0.003} | 2 |
| Encoders only | Encoder hidden width {16, 32}; learning rate | 4 |
| Inference only | Inference hidden width {64, 128}; depth {1, 2}; latent width {32, 64}; learning rate | 16 |
| Encoders + inference | All preceding axes | 32 |

Each setting uses seeds 1, 2 and 3: **486 grid fits** across all three families.
Other controls follow the chosen 128-head reference: AdamW, weight decay 0.0001,
input/head/interlayer dropout 0.1, encoder/inference dropout zero, batch 32,
BPTT chunks 100, maximum 100 epochs, validation early stopping with patience 10.
All 486 models are trained fresh; no historical checkpoint is a fitting cache.

Mean validation log loss selects each family's winner within each condition.
Exact ties use fewer parameters, then candidate ID. The best validation-selected
deterministic inference configuration (with or without encoders) receives two
followups: Gaussian sampling with beta 0 and with beta 0.001. A separate plain
GRU control widens its ordinary prediction head to approximately match that
configuration's actual parameter count and searches both learning rates.
These are **36 additional fits**, including all three seeds/families.

Every primary and followup selection is frozen before test metrics are computed.
The main architectures always use a 128-unit head; only the explicitly labelled
capacity control changes its head width. Gaussian evaluation uses its mean.
Gaussian architecture/training settings are inherited from the deterministic
winner, not separately exhaustively retuned.

## Participant partitions and inference limits

The development partition preserves the earlier exact 70/15/15 participant
assignment and the 55,122 binary responses with 144 item and 36 skill identities.
Five outer participant folds use seed 20261103. Each outer training set reserves
20% of its participants for inner validation. The complete grid and followup
procedure repeats independently in each fold: **3,132 total research fits**.
Every response appears in exactly one outer test fold per condition and seed.

This dataset and development split were already inspected during architecture
development. Engineered-feature nonlinear parameters remain the predeclared
reference constants; they are not reestimated within folds. CV therefore checks
generalization across participant partitions conditional on those constants.
Seed averages describe individual models, not probability ensembles. Paired
participant bootstrap intervals condition on the selected fitted models.

## Execution and artifacts

`run-gru-encoder-study.R` requires an explicit `LKT_STUDY_LIBRARY` and a verified
release JSON containing the package version, source-archive SHA256 and installed
research-manifest SHA256. An incorrect library/release fails. No retired LKT
installation or loose package-source copy is used. Linux setup installs the
same maintained source archive into the study deployment library after checking
the archive and container checksums.

The setup job runs all native package regressions, freezes the plan and executes
12 one-epoch short-history smoke fits. These are separate from research results.
The grid job has 48 shards, at most eight concurrent six-worker shards (48 CPUs).
Dependent followup jobs freeze choices and replay selected predictions. The final
report independently recomputes every validation record, checks outer test
coverage, and writes all conditions without test-based winner selection.

Artifacts include `study.rds/.txt`, `candidates.csv`, participant assignments,
portable checkpoints, per-fit validation/training records, immutable selection
files, selected test predictions, pooled CV metrics, per-fold metrics, paired
participant contrasts, HTML reporting and verification records. Original fitted
models, old results, and submission records are never modified.
